# 离线汇报模板下一阶段开发计划

2026-11-25 · 基线 `b10bee3`（v9） · 开发分支 `codex/offline-html-next`

模板服务于现场汇报、原位改稿和会后审阅。用浅色的博客式文档保留原有阅读节奏，目录显示当前位置，固定批注栏集中处理反馈。阅读和汇报复用正文，所有可传递内容仍保存在一个 HTML 中。

| 顺序 | 交付 | 验收 |
| --- | --- | --- |
| 1 · 计划与选型 | 更新 PRD、批注设计和视觉规范。对比 Quarto、Slidev、Reveal.js、Notion，以及原生编辑、Markdown 和块引擎。记录实测体积、文件协议运行条件与往返风险 | 选型给出具体组件和锚点的保留条件，约定本轮组件边界 |
| 2 · P0 编辑与保存 | 直接打开 `file://`，验证当前文档后授权写回。处理文件外部变化、取消、保存失败、并发输入；保留冲突前的内存内容。加固锚点匹配、失联重绑和模式一致性 | Chrome 用可丢弃副本验证实际磁盘写回与重开；独立复测重名文件、外部修改和锚点歧义 |
| 3 · P1 审阅与组件 | 当前章节／全文、待处理／已解决／失联；固定独立滚动侧栏、页边标记、重叠选择、完成折叠、目录与精简工具栏。导出结构化 AI 修订指令。统一组件定义；先补页签、表格和轻量图表 | 操作可用键盘触达；正文、媒体、初始交互状态和批注一起写入／重开 |
| 4 · 整体验收 | 通用模板和 RSI 长文档，桌面和窄屏，阅读与汇报来回切换。拆开记录真实操作、模拟故障与未覆盖环境 | RSI 文件只在仓库外的临时副本测试。仓库只留通用内容、检查脚本及无业务内容的证据 |

## 视觉与交互基准

- 用原有系统字栈、白纸 `#ffffff`、灰绿底 `#f4f7f6`、正文深色、单一绿强调色。标题与正文左对齐，正文和抽屉使用同一边框与圆角体系。页边数字用于识别有批注的正文块。
- 工具栏保留当前标题、汇报、正文编辑、批注和文件状态。低频排版选项收入展开菜单。章节切换、阅读滚动、正文标题编辑三者更新同一当前位置。
- 右栏以细线分隔线程。引文可以定位，意图和状态用文字表达，回复为直接操作，编辑、重绑、解决或删除集中在更多操作。已解决线程默认收起，展开时正文清晰可读。
- 正文高亮和右栏条目支持预览，点击页边按钮时可明确选择重叠批注。窄屏用可关闭抽屉，定位后正文重新获得空间。支持键盘焦点和减少动态效果。
- 保留现有 HTML 作为正文和交互的权威源。选择保守的锚点恢复策略，对缺少定位证据的意见提供重绑。大型编辑器评估见[组件与编辑引擎调研](组件与编辑引擎调研.md)。
