# 内容组件与编辑引擎调研

2026-11-25，基线 `b10bee3`。本轮继续使用 HTML 正文作为唯一内容来源，在现有原位编辑之上扩展内置组件。面向 Markdown 的候选能力是单向导入，优先验证 Marked 加净化及资源校验后的体验。块编辑器需要同时证明实际需求、锚点迁移和组件保真，目前暂缓。

## 产品交互参考

| 产品 | 实际机制与离线边界 | 本项目采用的做法 |
| --- | --- | --- |
| Quarto | HTML 使用标题生成页签，`embed-resources: true` 可将样式、脚本和媒体打入单个 HTML。演示格式的双栏将两组内容分开定义。构建可自包含输出，动态外部资源仍需按文档检查。[HTML 文档](https://quarto.org/docs/output-formats/html-basics.html) · [Revealjs 演示文档](https://quarto.org/docs/presentations/revealjs/) | 页签用短标题组织同一主题的不同证据。双栏保留两侧各自的标题、段落和锚点。交付前检查所有运行资源。 |
| Slidev | 提供 `two-cols`、`two-cols-header` 和可复用 Vue 组件。标准 HTML 构建输出到 `dist`，官方用静态服务器预览，远程资源打包另有选项。[布局](https://sli.dev/builtin/layouts.html#two-cols) · [组件](https://sli.dev/builtin/components.html) · [构建文档](https://sli.dev/guide/hosting.html) | 共用组件接口，各内容区域有独立语义。避免将幻灯片路由和组件构建器带入最终报告。 |

视觉上采用约束更少的文档布局。标题、段落、图表顺序跟随正文，工具栏突出汇报、编辑与待保存状态。目录标示当前标题，批注保留独立滚动。边框和圆角只标示界面层级和可操作区域。宽表在组件区域内滚动。页签面板始终随文档保存，使用 `tablist`、`tab` 和 `tabpanel` 关联，支持方向键、Home 和 End，正文批注跳转可先激活所属页签。[WAI-ARIA 页签规则](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)

## 实测体积

每行将对应的实际 JS、CSS 按 `script`、`style` 内联至同一份基线 HTML，测量相同内容下的字节变化。未加密的原始字节是发送和打开 HTML 的直接成本。gzip 用于对比压缩归档体积。打包原型省略许可证注释，未计入正式集成适配代码、许可证文本、用户媒体和新组件。

| 原型 | 内联增量 / B | 完整 HTML / B | 完整 HTML gzip / B |
| --- | ---: | ---: | ---: |
| HTML 原位编辑，仓库基线 | 0 | 150,209 | 39,082 |
| markdown-it 14.1.0 发布版浏览器 UMD | 123,635 | 273,844 | 84,073 |
| Marked 16.2.1 + DOMPurify 3.3.1 | 61,301 | 211,510 | 59,362 |
| Marked + DOMPurify + Turndown 7.2.1 | 72,207 | 222,416 | 63,098 |
| ProseMirror 基础 Schema、View、历史与键盘编辑 | 211,402 | 361,611 | 105,036 |
| BlockNote 0.41.1 核心、默认块与样式 | 1,108,430 | 1,258,639 | 366,482 |
| BlockNote 0.41.1 + React 19.2.0 + 最小编辑视图和样式 | 1,979,018 | 2,129,227 | 582,217 |
| Reveal.js 5.2.1 核心展示运行时和 CSS | 165,884 | 316,093 | 79,633 |

Reveal.js 数据不含主题、Markdown 插件和附加功能。BlockNote 数据不含字体及完整工具栏界面。版本和组合决定体积，以上结果用于比较适用范围相同的本地构建。markdown-it、Marked、Turndown、ProseMirror 和 Reveal.js 的直接包为 MIT，DOMPurify 为 MPL-2.0 或 Apache-2.0，BlockNote 核心为 MPL-2.0。正式内联前需保留适用许可证并检查传递依赖。

## `file://` 和往返保真

macOS 26.6.2 arm64，Chrome 158.0.8127.37。独立测试页使用全新浏览器配置，通过 `file://` 加载。页面 CSP 禁止网络连接及外部资源，只允许内联脚本、内联样式及内嵌图片。浏览器另以 `MAP * ~NOTFOUND` 启动。各页记录 DOM 检查结果，涵盖中文文本中带格式的锚点、带类型的双栏和页签、表格、折叠块、data URI GIF、具备范围控件的示例图表。

| 原型 | 实际结果 | 集成边界 |
| --- | --- | --- |
| 原生 HTML 克隆、改字、重新解析 | 七项均保留。重新解析后，按块 ID 和偏移取出的引文一致，重新绑定的示例滑块可以更新读数 | 现有保存逻辑可以延续。原生试验只验证结构保真，完整文件写回见回归记录。 |
| markdown-it 与 Marked 单向解析 | 两者均生成 Markdown 表格。markdown-it 在 `html: false` 下把样例 HTML 当文本。Marked 加 DOMPurify 默认配置保留样例中的原始 HTML 页签和块 ID | 两者均需加入项目资源策略。Marked 默认净化仍可留下原有 `data-*`，导入时必须明确剥离或转换并新建 IDs。[markdown-it 配置](https://github.com/markdown-it/markdown-it/blob/master/docs/usage.md) · [Marked 文档](https://marked.js.org/) |
| HTML → Turndown 默认规则 → Marked + DOMPurify → HTML | 七项中保留了内嵌 GIF。原块 ID、组件类型和交互控件消失，样例表格及折叠结构未重建 | 增加表格扩展可以处理表格语法，组件与锚点仍需要独立模型。 |
| HTML → ProseMirror 基础 Schema → HTML | 编辑视图成功挂载。七项中保留了 GIF，原块 ID 和自定义互动结构丢失 | 可为每个组件定义 Schema 属性、解析与序列化规则，交互控件可用 NodeView。基础 Schema 的结果不能代表定制 Schema 的保真度。[ProseMirror 指南](https://prosemirror.net/docs/guide/) |
| HTML → BlockNote 默认 Schema → BlockNote 完整 HTML | 核心和 React 构建均保留了表格与 GIF。React 编辑区成功挂载。原块 ID、双栏、页签、折叠和交互图均未重建 | BlockNote 自有 JSON 和完整 HTML 可携带其 Schema 数据。从既有自定义 HTML 迁移仍需逐类映射。标准 HTML 与 Markdown 转换在官方文档中也有损。[支持格式](https://www.blocknotejs.org/docs/foundations/supported-formats) · [自定义 Schema](https://www.blocknotejs.org/docs/features/custom-schemas) |
| Reveal.js 内联核心 | 两页演示可在本地打开，第一次前进显示片段，第二次切换到下一页 | 试验验证演示运行时可离线封装。原位编辑、审阅与保存仍由产品实现。 |

往返试验主要核对结构和源属性，并补测原生示例滑块的重新初始化。GIF 动画、两栏／页签布局、实际报告的图表交互恢复、真实授权写回、真实长文档、中文输入法、其他浏览器和辅助技术需走产品验收。内联构建采用 IIFE，规避相对模块文件在 `file://` 下可能受到的 CORS 限制。写回仍取决于运行环境是否支持文件选择与授权，编辑引擎不改变权限行为。[MDN 模块说明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules/Modules_on_the_web) · [Chrome File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)

### 复测方法

1. 在临时目录用 Node 25.8.0、npm 11.11.0 安装固定版本，使用 `--ignore-scripts --no-audit --no-fund --save-exact`，保存 lockfile。取基线 `git show b10bee3:offline-report.html`。ProseMirror 依赖为 model 1.25.13、state 1.4.4、view 1.44.0、transform 1.12.7、schema-basic 1.2.4、keymap 1.2.3、commands 1.7.2、history 1.5.2。BlockNote 构建复用同一套 ProseMirror 版本。初测多个 model 版本共存，BlockNote 导入失败。将 model 统一为 1.25.13 后重新打包和复测。
2. 用 esbuild 0.25.12 的 `--bundle --minify --format=iife --define:process.env.NODE_ENV='"production"' --legal-comments=none`。Marked 入口调用 `sanitize(marked.parse(text))`，往返入口另调用 `new Turndown().turndown(root)`。ProseMirror 入口从基础 Schema 创建 DOM 解析器和序列化器，并创建使用历史、基础按键映射和官方 CSS 的 EditorView。BlockNote 核心入口调用 `BlockNoteEditor.create()` 并带核心 CSS，React 入口额外渲染 `BlockNoteViewRaw`，关闭工具栏及菜单。
3. markdown-it 单独使用发布包 `dist/markdown-it.min.js`。Reveal.js 使用 `dist/reveal.js` 和 esbuild 压缩后的 `dist/reveal.css`。将各产物对应的标签插在基线 HTML 的 `</body>` 之前，转义脚本正文中的闭合标签。按 `wc -c` 和 `gzip -n -9 -c 文件 | wc -c` 取值。浏览器测试用独立页内联同一产物，在 `Chrome --headless --dump-dom` 输出中核对 `output` 结果。

## 组件接口与实施顺序

| 优先级 | 内容 | 保存与批注要求 |
| --- | --- | --- |
| P0 基础 | 段落、双栏、折叠内容、图片／GIF | 沿用既有 `data-rsi-added` 类型和可编辑块，兼容旧报告。每个可批注部分有持久 `data-review-block`，宽窄屏顺序与 DOM 一致。 |
| P1 组件 | 页签、原生表格、媒体管理 | 页签显示状态与编辑内容分离，跳转时显露锚点。原生表格保留表头和单元格语义，宽表局部滚动。媒体只走本地选择、类型限制和内嵌。 |
| P1 图表 | 内置数据图表与既有交互图兼容 | 图表定义、数据及说明进入文件，控件按定义重新初始化。用户浏览时的临时控件状态按组件契约处理。旧版图表的结构和动作要单独回归。 |
| 后续评估 | Markdown 文档导入与块编辑 | Markdown 转换作为显式新内容导入，对原有正文、组件和锚点做增量变更。若拟迁移块引擎，应先为每类组件和旧数据写出迁移规则，并用通用与真实长文档验证。 |

组件定义统一声明类型、创建、初始化和保存边界。需要编辑的子内容通过同一正文块机制注册。资料导入生成新 ID，编辑已有内容沿用已有 ID。批注 JSON 保留块 ID、选区偏移、旧引文、上下文、意图和讨论状态。组件折叠、跨模式展示和页签切换共用同一节点，保存时清理临时控件与高亮，保留组件原始定义。有歧义的锚点保留原引文并交由用户重新绑定。
