# 离线 HTML 汇报模板设计

模板面向三件事：投屏连续讲解、讨论中修订和批注、将同一个 HTML 发给同事或交给 AI 阅读。新版沿用资料页原稿的 RSI 研究内容和两张交互图。投屏按章节切换，长内容滚动浏览。文件包含正文、样式、脚本、媒体和批注。连接本地文件后，修改写回该文件。

## 原版审查

| 使用步骤 | 原版表现 | 本次改动 |
| --- | --- | --- |
| 1. 打开文件，找到章节 | 有连续正文、分组目录及滚动定位。本次检查期间资料页还新增了阅读位置恢复、草稿保留和图表放大。 | 当前标题和保存状态持续显示。保留目录定位、草稿保留和图表放大。顶栏换行时按实际高度留出正文空间。 |
| 2. 投屏，并在现场改字 | 切章节时将整节缩放到一屏。进入正文编辑会退出投屏。 | 同一投屏页面内直接编辑标题、段落和表格文字。长章节保留字号并自然滚动。左右方向键切换章节，Page Up / Down 滚动正文。 |
| 3. 选中句子，与同事讨论 | 有选区高亮、批注、回复和完成状态。已有留言无法直接改，打开批注会退出汇报。 | 投屏可以直接批注。留言可修改，并标记“建议修改／请保留／讨论”。批注保留原句、当前引文及锚点状态。 |
| 4. 保存并交给别人 | 有桌面 Chromium 文件连接和自动写回。HTML 还内嵌了一份完整源码副本。 | HTML 只保留一份正文，保存时重建干净文件。写回前验证文档标识、版本和磁盘内容。有未保存改动时持续显示状态。 |
| 5. 插入材料，复用模板 | 既有图表可交互，布局和插图主要靠修改 HTML 源码。 | 编辑时可在当前章节末尾插入段落、双栏、折叠补充、图片或 GIF。可从文件菜单生成六节空白模板。 |

原版下载内容与资料页存档的 SHA-256 一致。上述发现来自源码及状态逻辑检查。本地文件预览被当前浏览器工具拒绝，未获取屏幕实拍。

## 文件与交互设计

- 阅读和汇报共用正文。目录在宽屏占左侧，在窄屏从侧边打开。浅灰背景、白色纸面和绿色交互状态来自原稿，圆角和阴影用于区分纸面、对话框和批注。断点和键盘规则参考 [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/434b7f91364665f2f733b310ec54809bf8f37937/command.md)。
- 投屏保留编辑和批注入口。每个章节是一页，内容超出一屏时可以滚动。双栏用保持阅读顺序的 CSS Grid，窄屏顺序堆叠。折叠补充适合放实验细节和背景证据。静态图片嵌入 HTML，GIF 通过点开和关闭控制播放，单张素材限 5 MB，素材的实际体积决定文件增长。[MDN CSS Grid 布局](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Common_grid_layouts)
- 批注 JSON 随 HTML 保存。每条保留章节、块 ID、选中文本、上下文、意图、线程和完成状态。编辑前文时更新位置，删除整段后保留原句并提示重新核对。“请保留”是给同事或 AI 的审阅意见。定位思路参考 [W3C Web Annotation Data Model](https://www.w3.org/TR/annotation-model/#text-quote-selector) 的文本引文和位置选择器。
- 正常使用走“连接原文件 → 选择当前 HTML → 允许写入 → 自动保存”。刷新或重新打开后重新连接。权限句柄只在当前页面存活，正文和批注以磁盘文件为准。支持查看的浏览器与支持写回的浏览器是两个口径。桌面 Chrome 或 Edge 按本机 API 和策略使用原文件写回，Safari、Firefox 和受限网页预览以阅读和导出副本为主。跨浏览器、零授权且覆盖原文件的组合超出现有普通网页权限。外部参考文献仅在点击链接时打开。[Chrome File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access) · [MDN showOpenFilePicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showOpenFilePicker)
- 直接在现有 HTML 上编辑正文，组件通过内置菜单添加。空白模板提供六个可改标题的节，现阶段以章节内编辑与插入为主。插入任意脚本、拖拽重排章节、富文本格式工具栏和完整 Markdown 往返属于后续扩展。

## Markdown 与块编辑器取舍

| 方案 | 合适的使用方式 | 代价 |
| --- | --- | --- |
| 原生正文编辑和内置组件 | 现场改文字、加图和对照卡。沿用现有 HTML 内容，可直接送给 AI 阅读。 | 仅开放预先定义的编辑位置，排版自由度有限。 |
| 内联 Markdown 解析器 | 常从项目文档粘贴长段落时，增加单向 Markdown 导入。预览净化后的内容，再写入独立的正文块。 | Markdown 本身缺少通用的双栏、动态图、批注语义。转换时要保留已有资源和注释。 [Marked 文档](https://marked.js.org/) |
| 内联 ProseMirror 或 Tiptap | 富文本、块拖拽及更细粒度的撤销成为主要工作流时，引入自定义节点和序列化。 | 需要实测打包体积、迁移现有文档、定义自定义节点的导入导出，另行验证跨浏览器行为。保存权限仍由浏览器决定。 [Tiptap Markdown](https://tiptap.dev/docs/editor/markdown) |

本次选择原生编辑。旧版原始文件约 281 KiB，修订版约 179 KiB，还未计入使用者额外插入的媒体。

## 验证边界

静态核对研究正文未改、41 个站内链接有效、无自动外部资源或浏览器存储调用、内联脚本可解析。用模拟文件句柄验证授权写回、磁盘冲突、写回失败及旧版本拒绝，另核对批注位移、删除后保留和 JSON 序列化。真实桌面文件选择器、移动端排版、投屏与 Safari / Firefox 行为未取得实机验证。实机验收应从本地打开副本，试改一段、添加并编辑一条批注、保存后关闭重开，核对正文和批注都在同一文件中，再试宽窄屏、双栏与 GIF。
