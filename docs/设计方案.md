| 项目 | 说明 |

## 1. 产品背景与目标

### 1.1 背景

研究和技术汇报通常从文档出发，需要同时展示长文本、表格、图片、GIF 和可操作的图表。使用 PPT 时，内容需要再次拆页和排版，交互式组件也难以直接使用；讨论中产生的修改意见往往又散落在聊天、笔记或其他文件里。

产品以一个 HTML 文件承载整份汇报。汇报者可以连续阅读、按章节讲解，在现场修改正文和记录批注，保存后把同一个文件交给同事或 AI 继续处理。模板应能用于不同研究和项目汇报；产品截图与界面测试统一使用通用演示内容。

### 1.2 产品目标

1. 从文档组织汇报，减少重复排版。
2. 阅读、汇报、编辑和批注共用同一份正文，切换模式不产生内容副本。
3. 正文、媒体、交互组件和批注随 HTML 一起保存、一起传递。
4. 在支持写回的环境中，修改直接保存到当前文件，日常使用不依赖反复另存为。
5. 提供浅色、简约、适合投屏的界面，以及易于复用的内容组件。

### 1.3 成功标准

汇报者能在完整文件内完成“打开 → 汇报 → 改正文 → 加批注 → 保存到原文件 → 关闭重开 → 发给同事”，且保存后的内容和媒体完整保留。

收件人只收到一个 HTML，在目标浏览器中断网打开即可阅读和使用内置交互，不需要安装依赖、启动服务、登录账号或提前缓存资源。AI 直接读取 HTML 时，能找到正文、对应引文和明确的修改／保留意见。

### 1.4 当前实现基线与功能状态

本节依据仓库 HTML 的代码及独立回归记录描述已具备的能力。“已实现”表示已有功能入口与实现；只有记录了环境和操作结果的用例才能称为“已验收”。后文的“应”“必须”仍是产品要求，不能据此推断全部已经交付。

仓库以 [offline-report.html](../offline-report.html) 作为唯一模板入口，预填六个通用主题、双栏、折叠补充和一条演示批注，可直接用于功能体验、截图和复测。用户可以替换演示内容，也可以从文件菜单生成清空正文与批注的新模板。

| 能力 | 当前实现 | 边界与验证状态 |
| --- | --- | --- |
| 阅读与汇报 | 连续阅读、按主题切换、上一页／下一页、左右方向键、长内容自然滚动 | 汇报内保留编辑和批注；不等同于浏览器全屏 |
| 正文编辑 | 对已有标题、段落、列表项、表格单元格等内容块开启原位编辑 | 以块内纯文本修改为主；粘贴转为纯文本，换行及回车合并为空格；无通用富文本工具栏 |
| 目录与排版 | 多级目录、抽屉、当前位置、标题联动；字号 15／16／17／18，行距 1.35／1.45／1.55／1.65 | 修改已有标题可同步目录；尚无章节增删、拖拽重排入口 |
| 选区批注 | 浮动入口与快捷键、署名与回复、随正文／集中列表、双向定位、联动高亮、激活连接线、长内容折叠、解决／重开、失联重绑及清单导出 | 两种视图共用数据；窄屏使用列表；不提供多人在线同步或内置 AI 调用 |
| 原文件写回 | 用户授权连接、约 650 ms 延迟自动保存、手动保存、断开／重连、文档及版本核对、外部修改后暂停 | 桌面 Chrome 的本机 HTTP 实际写回已有记录；本地双击路径和其他浏览器未完成验收 |
| 插入组件 | 段落、双栏对照、折叠补充、图片／GIF 四个菜单选项 | 追加到当前主题末尾；可删除组件并保留相关批注；无插入表格或任意组件的菜单 |
| 媒体与放大 | PNG／JPEG／WebP／GIF 内嵌；图片描述必填；单张最大 5 MiB；GIF 展开加载、关闭移除 src；图表弹窗放大 | 提供图表放大容器；通用模板不预置业务图；无通用图表编辑器或第三方组件导入器 |
| 空白模板 | 生成背景与问题、概览、方案设计、验证与证据、讨论、总结六节，清空批注并产生新的文档标识 | 新文档通过下载创建；后续编辑仍走原文件连接流程；初始化不依赖任何业务示例图 |
| 离线与文件结构 | 样式、运行脚本和批注内联；媒体插入为 data URL；未使用云端接口或浏览器草稿存储 | 无用户媒体的主模板约 147 KiB；精确大小与哈希见回归记录；空白模板复用同一运行时 |
| Markdown／块引擎 | 尚未接入 | Markdown 清单导出只针对批注，不等于 Markdown 正文导入或编辑；见第 8 节 |

本轮通用模板补测覆盖空白生成、六个主题、汇报内编辑、批注、双栏、折叠补充、导出重开及宽窄屏。历史原文件写回实测仍按原记录的版本与打开方式引用，不能由新截图推导为已经在新环境复测。

## 2. 用户与使用场景

| 用户 | 场景 | 需要完成的任务 |
| --- | --- | --- |
| 汇报准备者 | 将已有研究资料整理成汇报 | 调整标题和文字，插入对照内容、图片、GIF 与交互图 |
| 现场汇报者 | 投屏讲解，并根据问题临时修改 | 切换章节、定位标题、放大图表，在汇报模式内编辑 |
| 讨论参与者 | 对具体句子提出意见 | 选中文字，记录建议、保留理由、讨论问题及回复 |
| 文件接收者 | 会后独立阅读或继续编辑 | 打开同一个文件，查看完整内容和批注 |
| AI 辅助修订者 | 根据文件中的审阅意见改稿 | 读取批注对象、原句、意图和处理状态，避免误改被要求保留的内容 |

本产品面向单人编辑和文件传递。多人可以围绕同一份文件讨论；不同人同时编辑各自副本后的自动合并不属于基础范围。

## 3. 产品范围与优先级

P0 为完整使用链路必须具备的能力；P1 为经过独立评估后增加的效率功能，不作为基础版本的前置依赖。

| 优先级 | 范围 |
| --- | --- |
| P0 | 单 HTML 离线交付；阅读与汇报模式；汇报内正文编辑；侧边目录和当前标题；选区批注及批注编辑；受支持环境中的原文件写回；图片与 GIF 内嵌；双栏、折叠内容及既有交互组件展示；空白模板复用；宽窄屏适配 |
| P1 | Markdown 导入／编辑；块编辑引擎；组件与章节拖拽重排；自定义组件导入；更丰富的文本格式工具 |
| 基础版本之外 | 云端协作、账号系统、联网 AI、在线同步、PPT 像素级排版、任意网页或脚本嵌入、全平台免授权覆盖原文件 |

“基于文档”首先指从文档内容生成或整理初始 HTML。直接读取资料空间、Word、PDF 或 Markdown 并自动转换，是另一项导入能力，不因存在示例内容而视为已经支持。

## 4. 信息架构与主要流程

### 4.1 页面组成

| 区域 | 职责 | 交互要求 |
| --- | --- | --- |
| 顶部工具栏 | 当前标题、模式切换、编辑、批注和文件状态 | 操作名称明确；换行后不遮挡正文；主要操作可一直找到 |
| 左侧目录抽屉 | 展示章节层级、定位和折叠目录 | 与正文标题对应；当前条目高亮；收起后可重新打开 |
| 正文区域 | 阅读、讲解和原位编辑 | 文字、图表和交互组件共用同一内容结构 |
| 右侧批注区域 | 引文、意见、回复和处理状态 | 宽屏位于正文旁；窄屏采用可关闭面板 |
| 组件插入入口 | 添加预定义内容组件 | 明确插入位置、必填内容和失败原因 |
| 图表查看层 | 临时放大图片、表格和交互图 | 关闭后回到原位置，不丢失图内操作或正文修改 |

### 4.2 内容准备

打开已有 HTML 或创建空白模板，修改章节标题和正文；通过插入菜单添加材料。准备者可以先编辑再连接文件，但未写回状态必须清楚显示。资料来源和研究结论由正文表达，模板不自动替用户改写内容。

### 4.3 现场汇报与讨论

进入汇报模式，按章节讲解。用户可通过目录或上一节／下一节切换；遇到长内容时滚动阅读。需要修订时直接开启正文编辑；需要讨论时选中句子添加批注。编辑和批注均不应迫使用户退出汇报模式。

### 4.4 保存与交付

在支持写回的环境中，用户点击“连接原文件”，选择当前 HTML 并允许写入。授权成功后，后续修改自动写回同一文件。显示“已保存”后关闭并重开，核对内容，再直接发送该 HTML。

收件人无需继承发送者的文件权限即可阅读。若要继续编辑并写回，由收件人重新连接其本地文件。

## 5. 功能需求

### 5.1 FR-01 文档内容与模板复用（P0）

**当前实现：** 当前已提供六节空白模板生成；内容主要通过既有块编辑与四类插入组件组织。章节增删、自动文档导入和通用块重排尚未实现。

- 支持标题、段落、列表、引用、表格、代码、图片、GIF 和内置交互组件。
- 结构化内容应使用统一样式，日常编辑不需要逐项调整绝对坐标。
- 提供与具体研究主题分离的空白模板。创建新文档时清空示例正文和批注，保留样式与功能。
- 修改标题后，目录和当前标题同步更新。
- 模板自身只维护一份正文；阅读态和汇报态不各自保存一套内容。

### 5.2 FR-02 阅读与汇报模式（P0）

**当前实现：** 当前已实现阅读／汇报切换、主题翻页、目录跳转和自然滚动；两种模式共用正文。

- 阅读模式连续展示全文，方便查阅、选择和讨论。
- 汇报模式按主题／章节展示，支持上一节、下一节及目录直达，并显示当前位置。
- 汇报模式保留编辑、批注、插入和文件状态入口。
- 长章节保持可读字号并允许滚动，不为塞进一屏而无限缩小文字。
- 切换模式后保留已编辑内容、批注和相关组件状态；不因视图切换丢稿。
- 支持键盘切换章节。焦点位于文本输入或交互组件内时，不抢占其光标与操作按键。

汇报模式是一种讲解布局，不等同于浏览器全屏；全屏能力不作为正文编辑的前置条件。

### 5.3 FR-03 正文原位编辑（P0）

**当前实现：** 当前实现是选定内容块内的纯文本编辑，支持中文输入；粘贴的格式与换行不会保留。跨块结构编辑、富文本格式与完整撤销历史不属于已有能力。

- 用户通过明确的编辑入口修改标题、段落、列表和表格单元格。
- 正在编辑的位置与普通阅读状态可以区分；退出编辑后去除编辑辅助标记。
- 在汇报模式中编辑，不自动切回阅读模式。
- 编辑普通文字时保留所在组件的结构和内置交互，避免误删整个图表。
- 文字粘贴不得引入外部页面的脚本、联网资源或失控样式。
- 文本编辑应保留浏览器可提供的基本撤销能力；跨组件、跨重开的完整撤销历史为后续范围。
- 编辑产生的修改进入未保存状态；结束编辑不等于已经写入磁盘。

### 5.4 FR-04 目录与当前位置（P0）

**当前实现：** 当前已实现目录编号、折叠抽屉、滚动高亮及标题同步。目录由文档已有章节生成，没有单独的章节编排面板。

- 左侧按标题层级生成目录，支持展开、折叠与收起整个抽屉。
- 阅读滚动、章节跳转及汇报翻页时，目录高亮和顶部标题随之更新。
- 当前标题过长时允许截断，但应提供查看完整标题的方式。
- 窄屏目录以抽屉形式打开，关闭后正文使用可用宽度，不遗留侧栏空白。
- 锚点定位后标题和键盘焦点不被固定工具栏遮挡。

### 5.5 FR-05 正文关联批注与讨论（P0）

**当前实现：** 正文与右侧批注栏双向关联，支持随正文和集中列表、作者与多轮回复、联动高亮、激活连接线、折叠展开、解决／重新打开以及失联重绑。完整设计见[正文关联批注设计](批注设计.md)。

- 选中正文文字后，通过浮动“＋ 批注”或 Ctrl／⌘ + Alt + M 创建批注。被批注的文字保留低饱和度背景色标记。
- 新文档在宽屏默认随正文排列：按锚点纵向位置对齐卡片，重叠时自动避让。集中列表用于批量查看、筛选和处理，两种模式共用同一份数据。
- 正文和卡片支持双向定位与点击／悬停联动；悬停不自动滚动或展开。连接线仅在激活／预览且两端可见时显示，不长期覆盖正文。
- 卡片包含作者、时间、引文、意图、内容、回复及处理状态。长内容和讨论默认折叠，激活后完整展开。
- 支持编辑、删除、解决和重新打开；已解决的留言显示删除线，重新打开后恢复。筛选包括全部、待处理和失联。
- 保留“建议修改”“请保留”“讨论”三类意图。“请保留”表达审阅要求，不自动锁定正文。
- 批注栏可独立开启／关闭；关闭后正文仍有轻量标记，点击可重新查看。
- 通过段落 ID、字符偏移、原文与上下文维护锚点，正文编辑后更新位置。无法唯一匹配时保留批注与讨论，标记失联；支持重新选区绑定，并保留有限的旧锚点历史。
- 删除批注或含批注的组件时明确影响并提供确认，避免意见无意丢失。切换模式不清掉当前标签页中的未提交草稿。
- 窄屏使用集中列表抽屉；定位正文后收起，保证阅读空间。宽屏恢复原来的模式选择。
- 批注与讨论随 HTML 保存；清单导出是辅助操作。只将导出等链接操作显示为超链接，编辑、回复、删除、定位等保留轻量按钮。

后续可扩展笔记、疑问、修改建议和 AI 解读类型，并围绕选区开展多轮 AI 对话、整理为文档笔记。该部分属于后续范围；当前不内置联网 AI 或占位聊天入口，AI 仍可直接读取 HTML 中的结构化批注。

### 5.6 FR-06 原文件保存与状态反馈（P0）

**当前实现：** 当前已有连接原文件、自动／手动写回、版本冲突检查和失败后暂停；Ctrl／⌘ + S 调用保存，重新打开需再次连接。导出副本和创建空白模板是独立文件菜单操作。

原文件写回是编辑主流程。导出副本是受限环境中的补救方式，不作为该要求已满足的依据。

| 状态 | 用户看到什么 | 处理要求 |
| --- | --- | --- |
| 尚未连接、没有修改 | “连接原文件” | 可正常阅读，允许开始编辑 |
| 尚未连接、已有修改 | 明确的“未保存”状态 | 保留当前内容，引导连接文件 |
| 已连接、有待写回修改 | 等待保存或正在保存 | 自动写回，避免同时发起冲突写入 |
| 写回成功 | “已保存” | 仅在磁盘写入完成后展示 |
| 用户取消授权／权限失效 | 未保存及重新连接入口 | 保留当前编辑，不伪报成功 |
| 选择了其他文档／旧版本 | 无法安全连接的原因 | 不覆盖错误文件 |
| 文件被外部修改 | 冲突提示 | 暂停覆盖，要求重新核对版本 |
| 磁盘写入失败 | 失败原因与下一步 | 保留内存中的修改，允许重试或显式导出副本 |

保存内容应包含正文、媒体、组件定义、批注及必要的文档设置。运行时弹窗、临时编辑表单和过渡提示不应固化成正文。写入期间又发生编辑时，后续修改仍须完成写回，不能提前清除未保存状态。

关闭或离开前，如仍有未保存内容，应在浏览器允许的范围内提示。因为不依赖缓存保存草稿，未经写回的修改不能承诺在异常关闭后恢复。

### 5.7 FR-07 内容组件与媒体（P0）

**当前实现：** 当前插入菜单只有段落、双栏、折叠补充、图片／GIF，插入位置是当前主题末尾。既有表格和交互图能够展示，但不能通过该菜单新建任意表格或交互图。

| 组件 | 使用目的 | 行为要求 |
| --- | --- | --- |
| 段落、标题与表格 | 讲清概念、数据及结论 | 文字可改，统一排版；宽表可在自身区域横向滚动 |
| 双栏对照 | 并列展示方案、前后变化、图与说明 | 两栏分别编辑；宽屏并排；窄屏按左后右的顺序堆叠 |
| 折叠补充 | 放置不必始终展开的背景或细节 | 展开／收起不影响正文和批注保存 |
| 静态图片 | 展示截图、结构图和结果 | 从本地选择后内嵌，提供描述，按比例缩放，可放大 |
| GIF | 展示动态过程 | 原始动态数据内嵌；提供明确播放／停止或展开／关闭控制 |
| 内置交互图 | 展示状态切换、局部对照或参数变化 | 保存及重开后仍可操作，放大时保留交互能力 |

组件通过统一入口插入当前章节，并提供移除方式。插入失败、格式不支持或素材过大时，需给出可执行提示。当前代码限制单张图片／GIF 不超过 5 MiB（5 × 1024 × 1024 B，界面提示为 5 MB）；将限制集中为配置项仍是维护要求。

“方便展示交互组件”不等同于可粘贴任意网页。基础组件和预置交互随模板内置；未来导入自定义组件时，必须将其依赖一起打包到 HTML，不能依赖远程 iframe、脚本或素材地址。

### 5.8 FR-08 轻量交付与分享（P0）

**当前实现：** 当前已有 HTML 副本导出、空白模板导出和批注 Markdown 清单导出；完整交付仍以 HTML 为准。

- 最终交付为一个可移动、改名、复制和发送的 `.html` 文件，无必需的同名资源目录或额外 JSON。
- 在文件中保留可读正文、清晰章节和结构化批注，便于人工及 AI 检查。
- 收件人首次打开即可阅读，不依赖发送者的浏览器账户、缓存、安装包或文件路径。
- 本地媒体应随文件内嵌；发送后不出现“发送者电脑上能看、收件人看不到”的依赖。
- GitHub 的源码页和聊天附件预览不作为运行环境；使用说明应引导用户下载 HTML 后用浏览器打开。

## 6. 视觉与交互规范

### 6.1 视觉方向

采用接近简约博客的阅读界面：浅色背景、白色正文区域、深灰文字和少量低饱和强调色。正文是视觉中心，目录和批注提供辅助，不把整篇内容切成同样大小的卡片。

圆角、边框和轻阴影用于区分正文、抽屉和批注卡片，对应层级共用圆角变量。随正文模式将卡片直接排列在文档留白区域，不额外套白色大容器；集中列表采用一个白色抽屉，条目用细线分组。引用仅保留竖线，普通段落不额外套卡片；不使用装饰性渐变、大面积动效或与汇报无关的首屏动画。

### 6.2 排版与布局

- 优先使用系统中文与西文字体，避免联网加载字体。
- 建立统一标题、正文、引用和辅助信息字号。阅读字号与行距可调；汇报字号要适合投屏。
- 批注控件使用稳定字号，不随正文字号一起放大。
- 正文左右边缘对齐；双栏间距、批注内边距和按钮高度遵循一致尺度。
- 宽屏可同时展示目录、正文和批注；空间不足时逐步收起辅助区。
- 窄屏支持 390 和 320 像素宽度，工具栏可换行；整页不因组件溢出而横向滚动。

### 6.3 可访问性与状态反馈

批注开关与目录使用一致的轻量过渡；随正文模式跟随文档，集中列表独立滚动。悬停只预览，点击或键盘激活后展开。完成的留言显示删除线。导出批注清单使用蓝色下划线，编辑、回复、删除和定位使用轻量按钮，均有清晰的悬停与键盘焦点反馈。

- 目录、抽屉、表单、图片控制和弹窗可用键盘操作；焦点清晰，关闭后返回触发位置。
- 按钮和输入框有可理解的名称；图标不能成为唯一语义提示。
- 图片有文字描述；图表状态不能仅通过颜色区别。
- 保存、失败和定位异常应提供可见反馈，并能被辅助技术读取。
- 只保留表达展开、收起、定位和反馈所需的轻量动画；遵循减少动态效果的系统偏好。
- 不禁用浏览器缩放，不用裁切遮盖实际内容溢出。

这些规范是验收要求，不意味着现有页面已经全部符合。

## 7. 离线、保存权限与兼容性

### 7.1 离线约束

HTML 内包含展示与编辑所需的 CSS、JavaScript、媒体和组件资源。不得依赖 CDN、远程字体、外部图床、在线编辑引擎或云端接口。

正文、批注和必要设置以文件为持久化依据，不以 localStorage、IndexedDB、Service Worker、浏览器 Cache API 或服务端草稿作为恢复前提。运行中的内存状态、浏览器自身的正常加载机制不等同于产品的草稿缓存。

外部参考资料可以保留为链接，但只在用户主动点击后访问；不影响断网时阅读当前文档。仓库说明文档的在线截图不属于离线 HTML 的运行依赖。

### 7.2 浏览器能力边界

普通网页直接写回本地文件需要浏览器支持相应 API、用户交互和明确授权，不能仅凭“打开了这个 HTML”就自动取得覆盖权限。[Chrome File System Access 说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)与[MDN showOpenFilePicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showOpenFilePicker)是实现和兼容性核对依据。

| 环境 | 产品目标 | 保存约定 |
| --- | --- | --- |
| 桌面 Chrome／Edge，且当前打开方式允许文件写回 | 阅读、汇报、编辑、批注和原文件保存的完整链路 | 特性检测通过后，由用户连接并授权当前文件 |
| Safari／Firefox，或缺少写回 API 的受限环境 | 优先保证阅读和交互；编辑能力单独验收 | 明确说明无法自动写回；显式导出副本仅作为补救 |
| 移动浏览器 | 优先保证窄屏阅读、目录和媒体查看 | 不承诺移动端具有桌面级原文件写回能力 |
| 内嵌预览、聊天附件、GitHub 源码页 | 提供下载与打开指引 | 不作为完整体验验收环境 |

“所有浏览器均可查看”与“所有浏览器均可覆盖原文件”必须分开说明。目标环境应按操作系统、浏览器版本和打开方式验收，不仅按浏览器名称判断。

直接双击本地 HTML 是目标交付路径，必须专项实测。本机 HTTP 可用于开发与定位问题，但其成功不能替代 `file://` 打开路径的验收。重新打开后允许用户重新连接文件；无需通过缓存保留授权句柄。

## 8. Markdown 与块编辑器的选型原则

### 8.1 基础方案

基础版本采用正文原位编辑和预定义内容组件，保持 HTML 作为唯一交付物。引擎是实现手段，不是必须增加的产品功能。

| 路线 | 适用需求 | 取舍与进入条件 |
| --- | --- | --- |
| 原生编辑＋内置组件 | 现场改字、加图、对照和讨论 | 基础路线；优先保证保存可靠、批注可定位和组件不损坏 |
| 内联 Markdown 解析器 | 经常从 Markdown 文档搬入长内容 | 先考虑单向导入与预览；需处理图片内嵌、HTML 净化及自定义组件映射 |
| 内联块编辑引擎 | 富文本格式、重排和撤销成为高频任务 | 需要定义双栏、GIF、交互组件与批注节点，验证迁移和序列化后再决定 |

Markdown 解析器不等于完整编辑器；引入块编辑器也不能改变浏览器的文件写回权限。

[Marked 官方文档](https://marked.js.org/)说明其解析结果不自动做 HTML 净化，因此不能直接把任意导入内容当作可信页面。[Tiptap Markdown 文档](https://tiptap.dev/docs/editor/markdown)提示批注等高级内容存在转换限制；不能假设已有批注可无损完成 Markdown 往返。

### 8.2 P1 引擎评估门槛

引入任何编辑引擎前，需要有一份独立选型结果，至少核对：

1. 选择的实际功能和去掉非必要扩展后的体积；提供最终 HTML 大小，而非仅引用包体积。
2. 所有依赖能否内联，断网首次打开是否正常。
3. 中文输入、选择、粘贴、撤销，以及目标浏览器之间的差异。
4. 双栏、媒体、交互组件和批注在导入、保存、重开中的完整性。
5. 许可、版本维护和数据迁移方式。
6. 从现有 HTML 迁移后出现错误时，能否保留原文件并安全回退。

没有通过这些检查，不将 Markdown／块编辑器列为基础版本的交付承诺。自动章节拆分和排版策略也应单独定义。

## 9. 文件内容与批注保存约定

当前批注格式为版本 4，保存模式偏好、署名、线程、回复、处理状态与锚点；新增作者和旧锚点历史。读取旧格式时容许新增字段缺失，作者不明则标为“未署名”。具体字段、UTF-16 偏移约定与失联恢复规则见[正文关联批注设计](批注设计.md)。

本节约束文件应表达什么，不绑定具体编辑器内部实现。

| 内容 | 必须保留的信息 |
| --- | --- |
| 文档 | 文档标识、格式版本、内容版本及必要的主题／排版设置 |
| 正文 | 标题层级、内容顺序、稳定的内容块对应关系 |
| 媒体与组件 | 内嵌资源、组件类型、参数及重开所需的初始定义 |
| 批注 | 作者、章节、目标内容块、原句、当前引文、定位上下文、意图、留言、回复、时间和处理状态 |
| 定位异常 | 原文变化或删除后的意见、失联状态，以及重新关联后的旧锚点历史 |

批注可借鉴 [W3C Web Annotation 的引文和位置选择器](https://www.w3.org/TR/annotation-model/#selectors)，结合原句、上下文和位置处理定位；不能只靠易变化的页面坐标。

文件内容应能被普通工具和 AI 读取。批注 JSON 中的特殊字符不得导致脚本截断或改变原文语义。保存后应可从文件重建编辑界面，而不是保存当时整个运行界面的截图或 DOM 残留。

## 10. 非功能需求与建议指标

以下数值是本 PRD 提出的初始验收指标，并非用户原始需求中已确认的硬性数值；应在定义参考设备和测试文档后复核。

| 维度 | 要求／建议指标 |
| --- | --- |
| 自包含 | 仅发送一个 HTML；断网、干净浏览器环境首次打开，核心资源缺失数为 0 |
| 轻量 | 无用户图片／GIF 的基础模板建议不超过 300 KiB；超过时说明新增能力与必要成本 |
| 媒体体积 | 当前单张限制为 5 MiB；导入前显示大小、媒体与运行时代码分项统计仍需完善 |
| 首次可用 | 在明确记录的参考设备上，以约 30 个主题、无外部资源的文档为基准，建议 2 秒内可阅读并操作 |
| 基本交互 | 上述基准下，翻页、打开目录和打开批注建议在 200 ms 内给出可见反馈；磁盘写入耗时单独测量 |
| 保存可靠性 | 已提示保存成功的内容，关闭重开后完整保留；不得出现丢批注、错版本覆盖或缺失媒体 |
| 稳定性 | 重复保存与重开不反复复制组件或内嵌源码，不因操作次数无故扩大文件 |
| 可维护性 | 配色、字号、间距和组件样式集中管理，模板功能与研究正文分离 |
| 用户控制 | 不静默请求网络、上传正文或覆盖未授权文件；异常有恢复入口 |

## 11. 验收标准与交付

### 11.1 完整文件验收用例

验收必须基于最终完整 HTML。组件预览、模拟文件句柄或仅检查文件存在，都不能代替实际授权、磁盘核对和关闭重开。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| AC-01 | 断网，在无既有缓存的目标浏览器中首次打开 | 正文、目录、样式、图片及内置交互正常；无自动联网依赖 |
| AC-02 | 进入汇报、编辑正文，再切换阅读／汇报 | 保持内容一致，汇报内可直接改字，未保存状态准确 |
| AC-03 | 通过滚动、目录和翻页定位多个主题 | 目录高亮与当前标题一致，定位不被工具栏遮挡 |
| AC-04 | 选区新建批注，编辑留言、回复并切换完成状态 | 引文与意见对应，操作可用，模式切换不丢失 |
| AC-05 | 在引文附近改字，随后删除或大幅改写引文 | 能保留关联时继续定位；无法定位时保留意见并明确提示 |
| AC-06 | 选择并授权当前文件，完成真实写回，关闭后重开 | 磁盘正文、批注、意图与处理状态一致；不依赖浏览器草稿 |
| AC-07 | 同一文档多次保存／重开，并在重开后再次编辑 | 可重新连接并继续保存；无重复组件或异常体积增长 |
| AC-08 | 取消授权、选错文件、撤销权限、制造外部修改或写入失败 | 不误报保存成功、不覆盖错误版本；当前内容仍可重试或显式导出 |
| AC-09 | 插入双栏并修改两栏，保存重开 | 两栏内容保留；宽屏并排，窄屏顺序正确 |
| AC-10 | 插入图片与真实多帧 GIF，播放／停止后保存重开 | 媒体仍在文件内，GIF 动画和控制有效，不只是显示第一帧 |
| AC-11 | 操作内置交互图、放大、关闭，再保存重开 | 交互能力保留；不会保存出临时编辑工具 |
| AC-12 | 用 1440、1024、768、390、320 像素宽度查看；测试长标题与长批注 | 内容可读、主要操作可见，抽屉和浮层不挡住焦点，无整页横向溢出 |
| AC-13 | 仅用键盘操作目录、批注、弹窗、媒体控制和编辑 | 焦点可见且顺序合理；快捷键不抢占输入或组件按键 |
| AC-14 | 创建空白模板，再保存并发送给另一位使用者 | 样式和功能保留，示例批注已清空；单文件可独立使用 |
| AC-15 | 直接以文本方式读取 HTML，并核对含特殊字符的批注 | 可识别目标正文、修改／保留意图、回复与状态；文字没有被错误转义 |
| AC-16 | 分别从本地双击路径和其他声明支持的打开方式运行 | 每条打开路径都有独立结果；不能用开发服务器的通过结果替代本地打开 |
| AC-17 | 同一段附近建立多条批注，展开其中一条再折叠 | 默认随正文排列，自动避让，卡片不重叠 |
| AC-18 | 切换集中列表，筛选全部／待处理／失联，并保留未提交回复草稿 | 两种模式共用线程，筛选数量正确，当前标签页草稿不丢 |
| AC-19 | 悬停、点击与关闭批注栏 | 悬停仅预览；激活后展开；连接线仅激活／预览显示；关闭后正文仍有轻量标记 |
| AC-20 | 整段替换或制造无法唯一匹配的原文，再重新选区绑定 | 原意见与回复保留，明确失联，重绑后定位正确且有旧锚点历史 |
| AC-21 | 设置署名、回复与解决状态后保存重开 | 作者、回复、状态、锚点及模式偏好一致；运行时卡片和连接线不写入文件 |

### 11.2 交付与验收记录

正式使用物为单个 HTML。仓库另提供使用说明、PRD 和独立测试记录；这些开发资料不是收件人打开 HTML 的必需依赖。
