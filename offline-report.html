1 要解决的问题

1.1 训练仿真 RSI 要解决的问题

大模型训练仿真 RSI 调研与设计

训练仿真 RSI 让 open_training_sim 根据真实训练的观测，一轮一轮改进对阶段耗时、整步耗时和峰值显存的预测。每轮要定位偏差、修正规则，并验证新版预测是否更准、这条规则能否解释原先的偏差。通过验证的版本成为下一轮的起点。

提高仿真能力，还是提高迭代仿真的能力？

改进对象要提高的能力本阶段定位
仿真器给定模型、并行策略和硬件，更准确地预测阶段耗时、整步耗时和峰值显存。当前主目标
改进仿真器的过程更准确地诊断、更有效地选测，以更少代价获得可信修正。远期研究方向

当前先回答：经过一轮轮真实反馈，仿真器本身能否持续变准。

2.2 三个步骤分别解决什么

RSI 迭代步骤意义
Step 1　定位误差仿真的偏差可能来自算子图建模错误，单个算子性能建模偏差，或infra编排调度等，或者来自多个方面。定位可以把范围缩小到有证据支持的建模环节。
Step 2　修正与精度验收修正误差，为未来的迭代提供可靠的预测和经验。在当前配置和预期使用范围内，修正后的阶段耗时与显存估计都足够准确，才有依据用它比较训练方案。
Step 3　验证根因定位到的原因可能来自上游传导，并非根本原因；或两处建模误差正负相互抵消，让总耗时碰巧贴近实测。验证根因是为了弄清楚误差产生的根本原因，也关系到后续迭代会不会把偶然的补偿当成经验。

三个步骤组成闭环。仍有偏差或证据不足时，带着新观测回到 Step 1。

2.3 四个模块与六项检查

诊断模块要核对什么对应PPT的六个层次
A　模型语义与数据依赖切分前要做哪些运算，张量形状和生产、消费关系是否正确。① 原始模型算子图的完整性、形状与依赖。
B　分布式工作图每张卡持有哪些分片，要执行哪些计算和通信，哪些工作必须先完成。② 并行切分后的本地形状。③ 框架新增的操作及必要依赖。
C　算子与通信成本给定本地形状和硬件条件，一次计算或通信花多久，输出和临时工作区占多少显存。④ 计算、通信与融合算子的耗时。⑤ 单次操作的显存占用。
D　执行调度与资源占用工作何时启动、等待或重叠，哪些等待拖长整步，哪些分配同时驻留形成峰值。③ 实际执行时序。⑤ 整步峰值显存。⑥ 流水线空泡与通信掩盖。

①–⑥ 沿用原 PPT 编号。③ 横跨 B、D，⑤ 横跨 C、D；实际从哪里查起，由观测到的偏差决定。

3 Step 1 定位误差

3.1 四模块总览

整步偏短可能来自少算工作、单项耗时估低或等待遗漏。先把差异落到可核对的训练对象，再沿建模依赖追踪。

模块核心内容与输出依赖输入检查内容与依据（对应六项检查）
A　模型语义与数据依赖描述一步训练的逻辑运算，给出前向、损失、反向和逻辑更新的全局算子、张量端口及必要依赖。模型与损失函数源码、模型配置、样例批次、参与求导的参数。① 对照参考训练实现，查算子有无缺失或重复、张量形状与数据类型是否一致、消费者是否接到了正确的输出。
B　并行切分与框架工作图按实际并行和框架配置给出每张卡的本地工作、通信组、收发字节和必要前驱。A 的全局图、实际并行配置、通信组、层到阶段的分配、框架版本及开关。② 对照框架分片记录，查切分轴、复制和本地形状。③ 对照计算图和通信记录，查新增操作的次数、参与组、消息量和必要依赖。
C　算子与通信成本给出单项计算、通信或融合工作在给定资源条件下的执行成本，以及一次调用所需的输出和临时空间。B 的本地工作、精度、融合范围与通信请求，外加设备、算子实现及给定的可用算力或带宽等条件。④ 对照同条件微基准或设备记录，查计算、通信和融合操作的耗时。⑤ 对照分配记录，查单次操作的输出和工作区占用。
D　执行调度与资源占用根据依赖、调度与资源竞争推导就绪、启动、完成及资源分配，给出阶段和整步耗时及各卡峰值显存。B 的工作图和张量使用关系、C 的单项成本与空间需求，以及流水、预取、资源共享和缓冲区复用规则。③ 对照调度记录，查微批顺序、预取提交与实际启动。⑤ 对照峰值快照，查同时存活的分配。⑥ 对照逐卡时间线，查空泡、通信暴露和整步耗时。

A → B → C，B 与 C 共同支撑 D。四模块在输入核实后可分别检查，定位顺序由证据决定。

3.2 对齐证据与观测口径

先对齐什么需要固定或说明的内容
配置与运行条件模型与框架版本、实际并行策略、设备映射、拓扑和输入批次。
训练对象层、微批、rank、张量端口、通信事务或物理分配。
观测口径计时窗口、跨卡时钟；活跃分配、分配器预留与设备总占用。
偏差与波动重复稳态观测估计波动；分别记录吻合、失配、不可比和证据不足。

先裁到可比窗口。若同一窗口仍有空档，再查主机提交、上游到齐或资源占用。

诊断输出要交代：哪个对象偏了多少，证据能追到哪里，以及下一项观测能区分什么。

3.3 A　模型语义与数据依赖

检查①：核对切分前的前向、损失、反向与逻辑更新，确认全局计算及张量关系。

核对环节具体内容
依赖输入同版本模型与损失函数源码、训练配方、求导参数、优化器更新规则和样例批次。
独立依据参考训练逻辑图与张量记录。静态建立依赖模板，再用同一实际批次核实动态形状和分支。
检查输出算子种类与次数；全局 shape / dtype；生产者、消费者与必要前驱；参数共享和梯度流向。
差异报告指出最早的形状或端口差异，列出缺失、多出和未识别工作，并说明覆盖范围。

多个逻辑算子与设备内核可以多对多对应。不能只凭内核数量判断模型算子是否齐全。

3.4 B　分布式工作图

检查②③：从 A 的正确语义出发，核对并行切分、框架新增工作和必要依赖。

检查对象核对内容独立依据

3.5 C　算子与通信成本

检查④及⑤的单项空间：固定工作、实现与资源条件，再核对耗时和分配。

核对对象必须匹配的条件输出与证据
计算与融合M / N / K、dtype、布局、内核与融合范围。同设备微基准；预测时长、实测中位数、波动和差值。
通信原语、通信组、每卡字节数、拓扑、算法和库版本。同条件通信测量；分别核对服务、同步等待和排队。
单次空间输出张量、临时工作区和实际物理分配。分配记录；明确大小、别名与统计口径。
并发条件同样的并发工作和可用资源条件。条件一致仍估错执行速度，继续检查 C 的成本响应。

独占耗时正确、并发时才变慢，应先与 D 核对并发关系和资源分配。不能把含等待的内核总时长直接当作纯服务成本。

3.6 D　执行调度与资源占用

检查③⑥：给定 B 的工作与依赖、C 的成本，核对实际执行安排及其影响。

从哪一时刻查要回答的问题核对依据
数据就绪哪个必要前驱尚未完成？是否来自上游负载或工作量？张量依赖、逐卡就绪和同步记录。
框架提交多个工作已就绪时，框架选择了谁？预取是否晚提交？流水策略、微批顺序与框架提交记录。
设备执行请求为何排队？谁占着端口、算力或带宽？设备轨迹和对应资源占用。
完成与消费哪段净等待挡住消费者？是否落在决定整步的路径上？消费者开算、阶段完成和相关卡的记录。

物理上发生重叠，并不等于通信延迟完全被掩盖。等待和执行中减速需要分别核对。

3.7 D　显存驻留与整步峰值

职责要核对什么
C：单项大小输出与工作区实际申请多少空间；同一物理分配只计一次。
B：张量关系分配在哪张卡、由谁生产和消费，哪些张量是别名或共享存储。
D：同时驻留申请、最后消费、释放和复用；预取、重计算与缓冲保留怎样影响峰值。
整步结果按同一张卡、同一时刻汇总不同物理分配，再取峰值。分别比较活跃、预留和设备总占用。

各类别出现在不同时刻的最大值不能直接相加。若单项大小正确但峰值偏差，继续查存活期和同时驻留数量。

Formula 提供解析聚合；Pipeline 在各流水阶段的代表卡上推导排程与驻留。定位真机最慢卡或峰值卡，还需覆盖相应卡的实测记录。

3.8 模块交界与误差传播

交界先核对什么定位判断
A → B同一全局张量与各卡分片。全局已错回查 A；全局正确、本地错查 B。
B → C同一计算的本地维度，或通信组与字节数。换上已核实工作量后，检查成本偏差是否仍在。
B → D同一微批的工作、必要前驱和消费者。漏工作或必要前驱查 B；齐全后再查提交与资源等待。
C 与 D开始前等待、执行区间和实际资源条件。并发与资源分配查 D；同条件下执行速度偏差查 C。

实测替换能缩小范围；误差随替换消失，仍不足以单独证明根因。Step 3 继续检验竞争解释。

3.9 双卡线性层案例

3.9.1 双卡线性层参考设置

只研究同一个线性层的前向片段。两卡对称、输入从 0 ms 就绪、没有其他工作。每次仅放入一个建模错误。

对象讲解设定
全局计算X[8,4] × W[4,4] → Y[8,4]
每卡输入与权重输入按行均分为 X[4,4]；权重分片为 W[2,4]。
权重收集两卡 AllGather 后，各自拥有完整 W[4,4]。FP32 下每卡从 32 B 变为 64 B。
参考成本与安排AllGather 为 2 ms，GEMM 为 3 ms；先在 0–2 ms 收集，再在 2–5 ms 计算，片段共 5 ms。

形状与毫秒数均为教学设定，不是项目实测；这些时长不代表微型矩阵的真实性能。

3.9.4 四种单一错误对照

单一错误预测发生什么变化应核对的首处独立失配
A：全局形状错误W[4,4] 误建为 W[4,2]；B 继而得到 [2,2] 分片。参考全局形状已不同。新形状成本未给定，不编造完成时间。
B：漏 AllGatherC 没收到通信请求；D 预测 GEMM 0–3 ms，片段为 3 ms。参考需要收集权重，B 却把完整权重视为已可用。
C：计算耗时估低GEMM 从 3 ms 误估为 2 ms；片段从 5 ms 变为 4 ms。相同工作与资源条件下，独立 GEMM 记录仍是 3 ms。
D：额外等待2 ms 权重已齐、资源可用；却等待到 3 ms 再计算，6 ms 完成。必要条件已满足后，执行安排平白增加 1 ms 等待。

A 的一处错误影响 B、C、D，仍然属于单一来源；“下游受影响”与“多个模块各有错误”需要区分。

4 Step 2 修正与精度验收

4.1 漏 AllGather 的修正

先固定已核实的 A、C、D，只补齐 B 缺少的权重收集工作及其必要依赖，再重新求值。

对象修正前候选修正
A 的语义全局形状正确。保留原规则。
B 的工作与依赖只有 GEMM，完整权重被当作已可用。加入两卡 AllGather，并要求 GEMM 等到完整权重。
C 的成本GEMM 3 ms；没有对应的通信请求。保留 GEMM 3 ms；对补齐的通信估价为 2 ms。
D 的求值GEMM 0–3 ms，3 ms 完成。沿原有规则求值：收集 0–2 ms，计算 2–5 ms。

把 GEMM 直接改成 5 ms，也能凑出总计 5 ms，却解释不了真实工作清单与单项 3 ms 的计算记录。

4.2 规则修正与参数校准

修正类型适用证据应形成的结果
规则修正操作、形状变换、依赖、调度或驻留机制本身有误。有触发条件的规则；例如分片权重在消费前必须重建。
参数校准工作与机制已核实，在相同条件下单项成本仍系统性失配。有适用范围的效率、带宽、启动开销等参数。

三类数据各有用途

数据作用
校准配置提出规则或估计参数。
独立留出配置检验新形状、消息量和并行组合的预测。
已有稳定配置检查退化，防止修好当前案例却损坏原有正确预测。

反复根据某份验收结果挑规则或调参数后，它已经参与开发；最终结论要另用独立数据检验。

4.3 论文与工业实现

工作已经实现的方法本项目可以借鉴什么
G-SimICML 2025语言模型提出结构，GFO / SBI 估计参数；诊断差异反馈到下一轮结构改进。将规则提议与数值校准分开。它研究通用仿真，训练场景的独立精度与归因判据仍需定义。
Simthesizer2026 预印本按语义规格、组件映射、实现分阶段推进；依据运行、测试和验证反馈局部修正。让修正回到产生错误决策的环节。它面向 LLM 推理服务，不能直接视作训练 RSI 的完成方案。
SimuMax工业开源实现实测目标形状的算子效率；用 nccl-tests 等拟合通信带宽与延迟，写入系统配置。复用机器条件下的成本校准流程。共享流程中最终回写仍有手工步骤，不能称为完整自动 RSI。

4.4 精度与退化验收

5 Step 3 验证根因

5.1 误差起点与下游症状

定位到某个异常输出，不等于已找到产生它的那条错误规则。单一错误可以沿建模依赖传播到多个模块。

传播环节案例中看到的差异能否据此认定本模块规则有错
B 漏掉必要工作没有 AllGather，完整权重被当作已经可用。参考工作清单直接支持 B 的规则失配。
B → C没有对应的通信成本条目。不能。C 可能只是没有收到通信请求。
B → D 与 C → D预测 3 ms 完成，参考片段需要 5 ms。不能。D 可能在正确执行不完整的工作与成本输入。

根因验证要检验“错误从哪里产生、怎样传下来”。当前案例仅允许一个错误来源。

5.2 局部干预与根因验证

先列出候选根因与各自的传播路径，再用小范围、限时、可逆的干预检验预言。干预前写明中间量和最终指标应如何变化，并设置匹配对照。

验证要点在训练仿真 RSI 中的做法
区分误差起点与下游症状将候选错误规则与受影响的 A–D 输出分开记录。
把路径变成预言修改前写明工作条目、权重就绪、单项耗时和片段完成应怎样变化。
小范围、可逆干预先在一个线性层片段中改变一个可控条件；保留匹配的对照运行。
中间量与最终指标共同检验看传播链上的量是否先按机制响应，再看目标指标。只改善最终值，归因证据较弱。

仿真内只替换 B，可以检验内部传播是否自洽。要支持真实机制解释，还需独立训练记录或受控测量。

针对双卡片段，比较“开始时只有分片”和“计时前已预装完整权重”两种条件。保持全局语义、GEMM 形状、精度、实现和硬件条件一致。

条件或中间量需要在片段内收集权重计时前预装完整权重

5.4 归因与验证的相关研究

5.5 采纳、补测与撤回

看到什么结果得到什么结论后续处理
中间量与目标指标均符合预言，独立精度及回归也通过修正与机制解释在已验证范围内得到支持。采纳候选，记录父版本、规则与适用条件。
只有最终时间接近，中间量不符合可能出现补偿或干预过宽；原归因支持不足。保留竞争解释，设计能区分它们的下一项观测。
关键中间量没有按机制响应当前解释受到了反证。降低其可信度，回到 Step 1 检查。
出现不可接受退化或真实 OOM 漏判候选不满足用途要求。撤回修改；不以局部改善换取整体采纳。

本阶段先验证单一来源下的错误传播与局部修正。证据不足时允许保留候选，不强行给出根因标签。
